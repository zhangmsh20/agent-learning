# AI Agent 教材逻辑与改造说明（2026-09 更新）

> 评估与校准日期：2026-09-23

## 结论

2026-09 更新不推倒十章主线，而是把“Agent 能运行”升级为“Agent 能长时间、可恢复、可审计地运行”。

教材的十章主线成立，不需要推倒重来。它已经形成了从“是否应该用 Agent”到“怎样证明 Agent 可以上线”的完整链路。原稿的主要问题不是章节缺失，而是三种内容混在了一起：稳定原理、课堂实验和高频变化的平台资料。

本轮改造采用“稳定机制—可运行实验—平台观察”三层结构。正文首先解释不依赖厂商的机制；实验必须默认离线可跑；模型名称、价格和预览功能只作为带日期的观察，不写成永久结论。

## 十章逻辑

1. Agent 是什么：建立使用边界，防止所有问题都 Agent 化。
2. Token、上下文与提示词：解释一次模型调用的输入和输出契约。
3. 上下文工程：解释每轮如何选择、组织、压缩和缓存材料。
4. RAG：解决外部事实的发现、引用和检索评估。
5. 工具调用与 MCP：从“给模型资料”进入“让系统执行动作”。
6. 状态图：让多步任务可观察、可暂停、可恢复。
7. 记忆：讨论跨轮次、跨任务信息的写入、读取和治理。
8. 任务推进模式：比较工作流、单 Agent、多 Agent 和托管运行时。
9. 评估与可观测性：把质量标准变成数据集、grader、trace 和回归测试。
10. 安全、成本与产品化：把权限、审批、沙箱、凭据、延迟和运营连成上线条件。

这条顺序的关键因果关系是：没有上下文就无法理解 RAG；没有工具契约就无法设计状态；没有状态就无法讨论可靠的记忆和多 Agent；没有过程 trace 就无法评估和上线。

## 本轮改造边界

### 保留

- 电商客服贯穿案例。
- 概念先于框架、机制先于 SDK 的写法。
- 每章小结、练习和参考答案。
- RAG、状态、记忆、多 Agent、安全的基本章节顺序。

### 修正

- MCP `inputSchema` 的历史描述和最新版工具结果结构。
- 重复章节编号及残留的“新增、替换、补充”编辑标记。
- 已弃用的 OpenAI Evals Platform 实操路径。
- 硬编码的模型、价格、API key 和不可验证的成本结论。
- 脚本中“声称执行了动作但实际没有执行”的业务错误。

### 新增

- 统一 README、环境配置和自动验收。
- 长任务执行、compaction、sandbox、webhook 和托管式 Agent runtime。
- Tool search、动态工具表面和 programmatic tool calling。
- 短期凭据、私有 MCP 连接、成本上限等生产控制。
- checkpoint / resume、取消、幂等键和 trace 级评估。
- MCP 2026-07-28 的 `server/discover`、`resultType`、`input_required`、显式 handle 和弃用迁移。
- Computer Use / Browser Use 的沙箱、域名白名单、提示注入和人工审批。

## 教学验收标准

学完后，学习者至少应能完成以下任务：

1. 判断一个需求应该使用普通调用、固定工作流还是 Agent。
2. 设计一个最小且可验证的工具 schema。
3. 用状态图表达缺字段、工具失败、人工审批和恢复路径。
4. 为一个 Agent 建立常规、边界、安全和历史 Bug 四类 Eval。
5. 解释单 Agent 与多 Agent 的质量、延迟和协调成本差异。
6. 给出一份包含权限、日志、回滚和预算的上线检查清单。
7. 设计一个可中断、可恢复、可取消且不会重复执行副作用的 Agent 任务。

只会运行框架示例、不具备上述判断能力，不算完成课程。
